# AI Drama · 桌面应用实现方案（技术预研）

> 日期：2026-10-11
> 定位：**独立预研文档**，不属于 V4 迭代范围（V4 只管提示词与界面）。
> 目标：把现有"浏览器访问 `http://127.0.0.1:8008`"的形态，做成一个双击即用的桌面客户端。

---

## 一、现状盘点（决定改造量）

| 组件 | 现状 | 对桌面化的影响 |
|---|---|---|
| 后端 | Python 3.14 + FastAPI + uvicorn | 需与 GUI 同进程/同套打包 |
| 前端 | 原生 HTML/CSS/JS，由 FastAPI 静态托管 | **零构建**，可直接塞进任意 WebView |
| LLM 调用 | httpx 直连 OpenAI 兼容接口 | 纯 Python，无 Node 依赖 |
| 知识库选择 | `POST /api/kb/native-pick`：后端调 `powershell.exe` + COM `IFileOpenDialog` | **必须替换**（打包后/跨平台不可靠） |
| 配置/密钥 | `data/config.json`（明文 Key） | 桌面版应迁到用户目录 + 密钥库 |
| 数据 | 相对路径 `data/` | 需改为可写目录（避免装在 Program Files 后只读） |
| 启动方式 | `start.bat` / start.ps1 起 uvicorn + 开浏览器 | 换成 GUI 窗口 + 后台线程起 uvicorn |

结论：**前端零改动即可复用**，主要工作量在"进程宿主 + 原生对话框 + 目录/密钥 + 打包"。

---

## 二、方案对比

| 方案 | 技术栈 | 体积 | 改造量 | 体验 | 结论 |
|---|---|---|---|---|---|
| **A. pywebview**（推荐） | Python + 系统 WebView | ~40–80MB | ★最小 | 良好 | 与本项目天然契合 |
| B. Tauri | Rust + WebView2 | ~10MB | 中（需 Rust + sidecar 打包 Python） | 最佳 | 长期最优，链路长 |
| C. Electron | Node + Chromium | ~150MB+ | 中（需 Node + Python sidecar） | 好 | 体积大，双运行时 |
| D. PyInstaller + 默认浏览器 | Python | ~40MB | 最小 | 差（仍有浏览器外壳） | 过渡方案 |
| E. 纯 Web（PWA） | 浏览器 | 0 | 无 | 中 | 仍需起服务，不算桌面端 |

**推荐 A（pywebview）**：复用现有后端与前端，改动集中在启动壳与文件对话框；后续若要"极致体验"再迁 B。

## 三、推荐方案 A：实现链路（pywebview）

### 3.1 进程模型

```
GUI 主线程（pywebview）
  └─ webview.create_window(url="http://127.0.0.1:<port>")
       └─ WebView 渲染现有前端
后台线程（uvicorn.Server）
  └─ backend.main:app  （复用，无需改动业务）
```

- GUI 必须在主线程；uvicorn 用 `threading.Thread(daemon=True)` 起。
- 窗口关闭 → `server.should_exit = True` → 进程退出。

### 3.2 启动壳骨架（`desktop/app.py` ★新增）

```python
import socket, threading, webview, uvicorn
from backend.main import app

def free_port(preferred=8008) -> int:
    for p in (preferred, 0):
        with socket.socket() as s:
            try:
                s.bind(("127.0.0.1", p)); return s.getsockname()[1]
            except OSError:
                continue
    raise RuntimeError("no free port")

def run_server(port: int, server_holder: dict):
    config = uvicorn.Config(app, host="127.0.0.1", port=port, log_level="warning")
    server = uvicorn.Server(config)
    server_holder["server"] = server
    server.run()

def main():
    port = free_port(8008)
    holder = {}
    threading.Thread(target=run_server, args=(port, holder), daemon=True).start()
    webview.create_window("AI Drama", f"http://127.0.0.1:{port}",
                          width=1440, height=900, min_size=(1024, 680))
    webview.start()                      # 阻塞直到窗口关闭
    if holder.get("server"): holder["server"].should_exit = True
```

### 3.3 待办链路（按顺序）

| 步骤 | 内容 | 落点 |
|---|---|---|
| 1 | 端口探测（8008 被占自动换端口）+ 单实例锁 | `desktop/app.py` |
| 2 | 数据目录解析：`AIDRAMA_DATA_DIR` 环境变量 → `%APPDATA%/AIDrama/data` → 退回项目 `data/` | `backend/config.py`、`backend/main.py` |
| 3 | API Key 迁到系统密钥库（`keyring`），`config.json` 只存非敏感项 | `backend/config.py` |
| 4 | **原生文件夹选择**：pywebview `create_file_dialog(webview.FOLDER_DIALOG)` 暴露为 JS API，替换 PowerShell 方案；无桌面会话时降级为手输路径 | `desktop/app.py` + `backend/main.py` |
| 5 | 长任务反馈：群聊一轮可能 5–8s，前端已有 typing 占位；可加"取消"（`asyncio.Task` 取消或标记） | `frontend/app.js` |
| 6 | 托盘 / 关闭行为（最小化到托盘、退出确认） | `pystray` + `desktop/app.py` |
| 7 | 系统通知（"某角色回复完成"） | `win10toast` / `plyer` |
| 8 | 打包 | PyInstaller / Nuitka（见 3.5） |
| 9 | 安装包 / 便携版 | Inno Setup（安装器）/ 直接 zip（绿色版） |
| 10 | 自动更新（可选） | 版本检查 + GitHub Releases 下载 |

### 3.4 与现有接口的对接

- 现有 REST 接口全部复用；只需把"选文件夹"从 `POST /api/kb/native-pick`（PowerShell）换成 pywebview 原生对话框。
- 前端 `📂 浏览` 按钮改为优先调用 `window.pywebview.api.pick_folder()`；失败再回退到旧接口（浏览器形态仍可用）。
- 这样**同一套前端**同时服务"浏览器形态"和"桌面形态"，无需分叉。

### 3.5 打包要点（PyInstaller）

```
# 关键项
--noconsole
--name AIDrama
--add-data "frontend;frontend"          # 静态资源
--add-data "backend;backend"            # 若按包导入需保证 import 路径
--hidden-import uvicorn.logging
--hidden-import uvicorn.loops.auto
--hidden-import uvicorn.protocols.http.auto
--icon assets/aidrama.ico
```

- `Path(__file__).resolve().parent.parent` 在冻结后指向 `_MEIPASS`，`backend/main.py` 的 `ROOT/FRONTEND_DIR` 需改为**基于 `sys._MEIPASS` / `sys.executable` 的可写目录**解析（配合 3.3 第 2 步）。
- 首次启动在用户目录生成 `data/`，避免 Program Files 只读。
- 体积优化：`--exclude-module` 掉未用的大包；`upx` 可选（注意杀软误报）。

### 3.6 跨平台

| 平台 | WebView | 备注 |
|---|---|---|
| Windows | WebView2（Win10+ 一般自带；旧机需装 Evergreen Runtime） | 安装包内可带引导 |
| macOS | WKWebView（系统自带） | 需 `.app` 签名/公证 |
| Linux | webkit2gtk | 依赖系统包，发行版差异大 |

## 四、备选方案 B：Tauri（长期）

链路（比 A 长，但体验最好）：

```
1. 现有前端原样作为 Tauri 的 Web 资源（无需构建框架）
2. Python 后端打包成单文件 exe（PyInstaller --onefile）作为 Tauri "sidecar"
3. Tauri(Rust) 在启动时 spawn sidecar，探测端口，注入 URL
4. Tauri commands 暴露原生文件对话框（替代 pywebview 层）
5. 产物 ~10MB + sidecar(Python ~40MB)
```
- 优点：窗口/更新/签名生态成熟，体积小，跨平台一致性高。
- 成本：引入 Rust 工具链；sidecar 与进程管理（退出清理、孤儿进程）需处理。
- 建议：**先 A 验证体验，若需分发给非技术用户再考虑 B**。

## 六、风险与验证清单

| 风险 | 验证方式 |
|---|---|
| 端口被占 / 多开导致数据竞争 | 自动换端口 + 单实例锁；双开测试 |
| 冻结后静态资源找不到 | 打包后断网启动，确认前端可加载 |
| `data/` 不可写（Program Files） | 装到默认目录后新建会话、重启不丢记忆 |
| PowerShell 原生对话框在打包后失效 | 改为 pywebview 对话框并在 exe 内实测 |
| 杀软误报（UPX/PyInstaller） | 不启用 UPX；必要时代码签名 |
|
| 长任务期间窗口无响应 | 后端在子线程，UI 线程不阻塞；一轮 5–8s 有 typing 占位 |
| WebView2 未安装（老 Win10） | 安装器检测并引导安装 Evergreen Runtime |

**里程碑建议**：① 起壳（pywebview + 端口 + 线程）→ ② 对话框/数据目录/密钥 → ③ 打包可运行 exe → ④ 托盘/通知 → ⑤（可选）Tauri 迁移评估。

---

## 七、结论

- 用 **pywebview** 做桌面壳，是本项目**改造量最小、复用度最高**的路径：后端与前端几乎零改动，只需替换启动方式与文件对话框，并把数据/密钥放到用户可写目录。
- 打包用 PyInstaller -> 便携 zip 起步，需要正式分发时再上 Inno Setup 与代码签名。
- 若后续要对外分发并追求体积/体验，再评估 **Tauri + Python sidecar**。
