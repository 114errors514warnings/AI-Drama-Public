# AI Drama 群聊剧情模拟系统 — 初版实现方案

> 版本：初版（V1–V4 完整实现）
> 时间：2026-08 首次开发

## 一、目标与背景

需求文档《群聊剧情模拟说明文档.md》定义了 V1→V4 的多 Agent 剧情模拟演进路径：

- **V1 Dynamic Character Agent**：角色识别 → 知识库检索 → 动态 Prompt → 角色回复
- **V2 Agent Registry**：角色从"Prompt"升级为"Agent 实例"（独立记忆/状态）
- **V3 Agent Runtime Manager**：Agent 生命周期（create/destroy/pause/resume）
- **V4 World Simulation System**：导演调度 + 世界管理 + 时间线 + 事件 + 记忆

初版目标：不依赖 Langflow/LangGraph，用 **FastAPI + DeepSeek API** 从零实现以上全部功能，
并提供 **Web UI** 交互；同时满足两个特殊要求：

1. **多群聊并行**：允许同时运行多个群聊，不同群聊由不同 Agent 管理，从根源解决世界观串味；
2. **角色记忆持久化**：记忆保存到对应角色的记忆库，切换会话/重启服务不清空、不删除。

## 二、总体架构

```
SessionManager（多会话并行，一个会话 = 一个世界 = 一套独立 Agent）
│
├── 会话A「示例世界」  kb_path = D:\kb\demo-kb
│     ├── Director Agent（导演，独立身份发言）
│     ├── Agent Registry（A/B/C/… 各为独立 Agent 实例）
│     ├── Runtime Manager（create/destroy/pause/resume）
│     ├── World State + Timeline + Event（世界状态/时间线/事件流）
│     └── Memory Store → data/sessions/<A>/characters/<角色>.json
│
└── 会话B（另一知识库）… 完全独立的一套
```

关键点：
- 每个会话绑定一个知识库路径，`KnowledgeBase` 扫描并分类 md 文件；
- 切换会话只切换 UI 视图，**不销毁任何数据**；
- 每个会话的 System Prompt、检索索引、对话历史、记忆文件互不混用。

## 三、V1–V4 功能实现

### V1 动态角色 Agent
- `Character Selector`：LLM 从用户输入识别目标角色（JSON 输出，限定知识库角色列表）；
- `Character Retriever`：按角色名从知识库检索档案（文件名/标题匹配 + 别名解析）；
- `Prompt Builder`：组装「角色 System Prompt = 角色资料 + 世界背景 + 长期记忆 + 扮演规则」；
- 提供单角色对话接口 `POST /api/sessions/{sid}/chat/single`。

### V2 Agent Registry
- `agents.py`：`Agent` 数据类（agent_id / name / profile / system_prompt / status /
  emotion_state / relationships / long_memory / skills），每个角色独立实例；
- `registry.py`：注册表（register/unregister/get/list）；
- `Character Factory`：按角色名从知识库构建 Agent 并注册；
- 明确拒绝"一个通用 Agent 切 Prompt"的错误方案。

### V3 Agent Runtime Manager
- `runtime.py`：`create_agent` / `destroy_agent` / `pause_agent` / `resume_agent`；
- 生命周期语义：destroy 前先保存记忆并标记 destroyed（重启不复活）；重建时恢复历史记忆；
- UI 角色面板提供「创建 / 暂停 / 恢复 / 销毁」按钮。

### V4 世界模拟
- `DirectorAgent`：用户输入 → 导演 JSON 决策（narration 场景描述 / participants 参与角色 /
  date+time_of_day 时间 / location 地点 / event 事件）→ 各角色依次发言（后发言者可见前面发言）；
- `World Agent`：可选的一致性校验（检查世界规则/时间合理性），结果仅内部记录，不写入转录；
- `Timeline / Event`：每轮记录时间、地点、事件；
- `Memory Manager`：短期记忆=群聊转录（最近 N 轮），长期记忆=每轮 LLM 抽取角色本人事实；
- 导演以「导演」身份在群聊中独立发言（场景描述归属导演）。

### RAG 知识库
- 目录/文件名含「人物/人设/角色/character」→ 角色档案；
- 含「规则/评判标准/rule」→ 世界规则；
- 其余 md → 世界观常识（关键词+二元组打分检索，注入角色上下文与导演规划参考）。

## 四、核心设计决策

### 1. 多会话并行隔离（解决世界观混淆）
- 一个知识库 = 一个世界 = 一套完整独立 Agent 集合；
- 切换会话不销毁数据；系统重启后从磁盘恢复全部会话与角色记忆；
- 唯一删除记忆的途径：UI 中显式删除整个会话（二次确认）。

### 2. 记忆持久化
```
data/sessions/<会话ID>/
├── session.json            # 会话元信息 + 世界状态 + 时间线 + 事件 + 梗概
├── transcript.json         # 群聊完整记录（短期记忆来源）
└── characters/<角色名>.json   # 角色专属记忆库（资料快照+情感+关系+长期记忆）
```

### 3. API Key 安全
- 仅启动时从**可选的**本地 Key 文件读取，保存在内存；
- 不写入代码/日志/接口响应/前端，只返回掩码；本文档同样只出现掩码示例。

## 五、技术栈与文件结构

```
模拟群聊对话/
├── backend/
│   ├── main.py            # FastAPI 应用 + 全部路由 + 静态托管
│   ├── config.py          # 配置（API Key 安全加载）
│   ├── llm_client.py      # DeepSeek 调用（chat / json 模式 / 重试 / 降级）
│   ├── knowledge_base.py  # 知识库扫描→分类→检索
│   ├── prompts.py         # 全部 Prompt 模板
│   ├── agents.py / registry.py / runtime.py   # V1-V3
│   ├── world.py           # V4 世界状态 + 时间线 + 事件
│   ├── director.py        # V4 导演 + 群聊/单角色编排 + 记忆抽取
│   ├── memory.py          # 记忆持久化
│   └── session.py         # WorldSession + SessionManager（多会话）
├── frontend/              # index.html / app.js / style.css（群聊 UI）
├── data/                  # 运行时生成（会话与角色记忆、config.json）
├── start.bat / start.ps1 / stop.bat / stop.ps1
└── requirements.txt / README.md
```

## 六、验证结果（初版）

- 单角色对话：A按人设回应（"练会儿投篮"）；
- 群聊导演调度：自动选出A/B/C，推进时间地点，生成旁白，角色依次发言；
- 世界常识 RAG：C回应引用"社团/学生会/值日"设定；
- 长期记忆落盘：C记忆文件出现"承诺请B和A吃晚饭"等条目；
- 多会话隔离 + 重启恢复：会话1 与 会话2 转录/记忆完全独立，重启后 Agent 状态正确恢复；
- 全程 API Key 仅以掩码出现。
