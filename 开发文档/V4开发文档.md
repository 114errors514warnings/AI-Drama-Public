## 一、为什么要做 V4

V3 已经解决了"能跑、可观测、可评测"，但**内容质量**这一层没动过。当前实测问题（截图 + 会话数据 + 代码核对）：

| # | 问题 | 现象 / 证据 | 根因 |
|---|---|---|---|
| P1 | **角色说话"AI 腔"重** | 句子工整、三段式、爱总结升华；用"仿佛/一丝/不禁/意味深长" | 无语言示例（few-shot），模型只能退回默认"AI 助手文风"补全 |
| P2 | **角色被诱导成"写手/审稿人"口吻** | 出现"陷阱卡/视角/R4/quality-gate"等场外词 | `knowledge_base.rules_text()` 把整个 `World/` 注入了角色 prompt，含 `写作辅助/Pipeline配置速查.md`、`修复技法手册.md`、`评判标准/*` |
| P3 | 世界观背景太长、混杂 | `world.rules` 实测 = 《Pipeline 配置速查》全文 | `World/` 只有"检索语料"一种角色，**没有区分「背景 / 规则 / 词条 / 文风 / 排除」** |
| P4 | 角色容易旁白化（写别人） | 旁白与对白混排、角色模仿第三人称描写 | 提示词只有负向"禁止"，缺正向示例；历史里旁白与角色发言同格式 |
| P5 | 用词保守、模板化 | 句式重复、词汇贫乏 | `temperature=0.7` 偏低，且未暴露 `frequency_penalty / presence_penalty` |
| P6 | 缺少"去 AI 腔"闭环 | 只有人设一致率裁判 | 无 AI 腔检测与回归剧本 |
| P7 | 观测面板出现乱码文本串 | `<span class="obs-badge pass">PASS</span>` 以纯文本显示 | `renderObservability()` 把含 HTML 的字符串再 `escapeHtml()` |
| P8 | 顶部信息行 / 调用图过长 | 单行塞满世界·知识库·时间·地点；调用图一行 `｜` 串 | 缺格式化与分层 |

**V4 目标**：把"角色为什么像 AI"从提示词层根治，并把界面整理到可用、可读。

## 二、参考：SillyTavern 的提示词体系（概念对照）

V4 直接借鉴 SillyTavern（ST）成熟的角色卡与上下文拼装机制：

| ST 概念 | 作用 | 本项目对应 |
|---|---|---|
| `description` | 人设 / 身份 / 外貌 | 角色卡「基本」+「人物气质」 |
| `personality` | 性格标签 | 角色卡「性格核心」+「关键标签」 |
| `mes_example` | **对话示例（最强去 AI 味手段）** | 角色卡「对话示例」+ 世界「文风」 |
| `first_mes` | 开场白 | 角色卡「开场白」（可选） |
| `scenario` | 当前场景 | 世界状态（时间/地点）+ 本轮旁白 |
| `system_prompt` | 主系统提示 | 核心规则 + 场外隔离 |
| `post_history_instructions` | 历史之后追加的强指令 | 「轮到你说了」引导 + 硬约束 |
| **World Info / Lorebook** | 关键词触发的世界观词条 | `World/` 词条（新增 keys 机制） |
| `constant` 条目 | 常驻注入 | 世界观背景 + 硬规则 |
| `position / depth` | 注入位置与深度 | 常驻靠前、强调靠后 |
| `Author's Note` | 固定深度的强调 | 深度提示（本轮风格强调） |
| Context Template | 上下文拼装顺序 | §4.1 拼装顺序 |
| Instruct Mode | 用户/角色前缀、分隔符 | 群聊记录「角色名：」格式 |

**ST 社区公认的"去 AI 味"结论**：`mes_example` 的收益远大于任何"禁止清单"。因此 V4 的核心是**给每个角色加语言示例**，而不是继续堆规则。

## 三、V4-1 知识库结构化规范

### 3.1 目录约定重构（解决 P2/P3）

现状：`World/` 全部当检索语料。V4 改为按**用途**分目录，只有前四类进角色 prompt，`排除/` 永不注入：

```
<知识库>/
├── Character/<角色名>.md        # 角色卡（结构化，见 3.2）
├── Memory/<角色名>.md           # 角色初始长期记忆
├── World/
│   ├── 背景/                    # constant：世界观背景（常驻注入）
│   ├── 规则/                    # constant：硬规则（常驻注入）
│   ├── 词条/                    # selective：关键词触发的 lorebook 条目（见 3.3）
│   ├── 文风/                    # 全局文风规范（见 3.4）
│   └── 排除/                    # 写作辅助 / 评判标准 / 草稿 / 大纲 —— 永不进角色 prompt
└── Style/文风.md（可选）        # 等价于 World/文风/，两者取其一
```

**兼容策略**：若不存在 `World/背景` 等新目录，则按旧的"全量语料"行为回退，但**强制排除**下列路径名（现有 `SKIP_RE` 扩展）：
`写作辅助`、`评判标准`、`风格相关`、`草稿`、`备份`、`大纲`、`模板`、`名录`、`README`、`.obsidian`、`.backup`。
→ 这一步即可立即消除 P2（把 Pipeline 速查 / 修复技法 / 陷阱卡踢出角色 prompt），是**低风险、高收益**的先行改动。

> **实现口径（已落地）**：结构化世界观的**启用条件**是存在 `World/背景`（或 `World/词条`、`World/文风`、顶层 `Style/`）目录；
> 只要建立了其中之一，即启用"常驻（背景+规则）+ 词条命中"机制；否则回退为"全部未排除语料"。
> 排除名单**始终生效**，与是否启用结构化无关。

### 3.2 角色卡结构化模板（对齐你已有的 `人设提示词模板.md`）

你知识库里已有 `World/规则/设定/人物/人设提示词模板.md`，其结构与 ST 高度契合。V4 把它固化为**角色卡解析规范**（固定二级标题，缺项自动降级）：

```markdown
# A
<!-- 可选 YAML front matter -->
---
aliases: [小昕]
color: "#7c5cff"
---

## 性格核心        （1~3 句，ST: personality）
外冷内热，善良开朗。在朋友面前自然文静，在家族中压抑自我。

## 关键标签        （英文/中文关键词，供组合）
cheerful, gentle, carries inner burdens silently, struggles between duty and self-will

## 人物气质        （3~8 句，ST: description）
外柔内刚。人前开朗友善，独处时才露出敏感与不安。珍视友情胜过身份。

## 语言风格        ★新增（V4 核心，ST 里对应 system/post-history 的风格约束）
- 语速：偏慢，常在句首停顿「……」
- 句长：每句 ≤ 25 字，少用长句与书面语
- 口癖：无奈时「唉」；被戳中时先「（停顿）」再转移话题
- 称呼：对用户称「你」；对B称「B」
- 标点：少用「！」；「——」每 3 句最多 1 次
- 禁用：成语堆砌、哲理长句、总结升华、排比

## 对话示例        ★新增（ST: mes_example，2~4 组）
<START>
用户：你今天怎么没精神？
A：（把书合上，愣了一下）……没什么，昨晚没睡好而已。
用户：骗人。
A：（笑了笑，别过头）真没有。倒是你，作业写完了？
<START>

## 场景 / 关系 / 武技 / 禁忌
（沿用现有自由文本，作为补充资料）

## 开场白（可选）  （ST: first_mes）
```

**解析规则**（`backend/character_card.py`）：
- 按 `## <标题>` 切块；标题做同义词归一（`性格核心|性格`、`对话示例|语言示例|示例`）。
- 命中「对话示例」→ 进 `examples`；命中「语言风格」→ 进 `style`；其余 → 进 `description`。
- **整卡缺失结构化小节** → 回退：全文当 `description`，`examples/style` 为空（与现状一致，不破坏存量 26 个角色）。

### 3.3 世界观词条（Lorebook，解决 P3）

`World/词条/*.md` 每文件一条，用 front matter 声明触发：

```markdown
---
keys: [社团, 组织, 学生会]
constant: false
position: before_char
depth: 4
priority: 10
probability: 100
---
社团活动都在放学后……
```

- `constant: true` → 每轮都注入（同「背景/规则」）。
- `keys` 命中当前对话/场景/参与角色 → 注入（`search_lore` 升级为词条匹配，替代当前的"整篇 md 打分"）。
- `排除/`、无 `keys` 且 `constant != true` 的文件 → 不注入。

### 3.4 全局文风规范（复用现有资产）

复用你已有的 `World/评判标准/文风评判标准.md`（H1 视角统一 / S2 对话自然度 / S3 副词密度 / S4 句式变化 / S5 对话节奏）作为**文风规范来源**：

- 其中**面向角色的部分**（S2/S3/S4 的口语化与去修饰）注入角色 prompt 的「说话方式」；
- 面向稿件的部分（H1/H2/H3、场景专项）只给 **Judge / World Agent** 使用，**不进角色 prompt**。

## 四、V4-2 提示词体系重构（核心）

### 4.1 角色 System Prompt 拼装顺序（Context Template）

参照 ST，从"资料堆叠"改为"身份 → 世界 → 人设 → 语感 → 示例 → 记忆 → 场景 → 硬约束"：

```
1 身份锚定        （你是 X，不是 AI/助手/写手）        ← 最前，防越界
2 世界观·常驻      （World/背景 + World/规则，截断）    ← constant
3 世界观·命中      （World/词条 关键词命中条目）         ← selective
4 角色·性格        （性格核心 / 关键标签 / 人物气质）
5 角色·语感        （语言风格 + 全局文风 S2/S3/S4）      ★新增
6 角色·语言示例    （对话示例 2~4 组，<START> 分隔）      ★新增（最重要）
7 长期记忆         （角色记忆，相关性排序取 top-N）
8 当前场景         （时间 / 地点 / 关系 / 本轮旁白）
9 群聊最近记录     （带「角色名：」前缀）
10 深度提示        （Author's Note：本轮风格强调）        ★新增
11 终局指令        （post-history：只输出角色对白，1~3 段）
```

### 4.2 角色 System Prompt 模板（可直接落地）

```text
# 你是谁
你是「{world_name}」世界里的「{name}」。你不是 AI，不是助手，不是小说写手——
你就是这个角色本人。此刻你正以「{name}」的身份，在一个熟人小群里和大家聊天。

# 这个世界（不可违背）
{world_constant}

# 此刻相关的世界片段
{world_selective}

# 你是个什么样的人
{character_core}
{character_traits}
{character_temperament}

# 你和用户的关系
{relationship_to_user}

# 你说话的方式（必须像下面这样）
{language_style}

# 你说话的示例（照这个语感说，别照抄内容）
{examples}

# 你记得的事
{long_memory}

# 现在的场景
时间：{time}　地点：{location}
{narration}

# 你和其他人的关系
{relationships}

# 规矩
1. 只输出「{name}」自己说的话，1~3 段，第一人称。不要替别人说话。
2. 可以用（动作/神态）补充自己，但不要写别人的表情、动作、心理。
3. 不知道就说不记得、不知道，不要编造设定，不要提 AI / 规则 / 系统。
4. 像真人聊天：可以打断、跑题、岔开、只回一个动作，不必有问必答。
5. 不要总结、不要升华、不要每句都工整对仗，不要用书面语和哲理长句。
6. 避免这些词：{anti_ai_blacklist}。
```

### 4.3 终局指令（历史之后追加，post-history）

在 `messages` 最后追加一条高权重 user/system 消息（ST 的 `post_history_instructions` 等价）：

```text
（导演旁白）{narration}

现在轮到「{name}」说话。用你自己的语气，像上面示例那样，说 1~3 段。
只写「{name}」的话，不要旁白别人，不要总结。
```

### 4.4 对话示例的写法（mes_example）

- 2~4 组，覆盖：**日常 / 情绪暴露 / 互动反应 / 被戳中后的转移话题**。
- 用 `<START>` 分隔；动作放 `（ ）`；示例中**不出现具体人名地名**（用"你"）。
- 示例要**故意不工整**：允许口语、省略、半句话、突然换话题。

```text
<START>
用户：你今天怎么没精神？
{name}：（把书合上，愣了一下）……没什么，昨晚没睡好而已。
用户：骗人。
{name}：（笑了笑，别过头）真没有。倒是你，作业写完了？
<START>
{name}：（盯着窗外看了好一会儿）……算了。说了你也嫌烦。
用户：说说看。
{name}：（顿了顿，声音低了些）就是……突然不太想努力了。你别笑。
```

### 4.5 反 AI 腔硬规则（负面词表，`backend/style.py`）

```text
仿佛、彷佛、宛若、宛如、犹如、如同、一丝、一抹、眼中闪过一丝、意味深长、
若有所思、嘴角勾起、嘴角微微上扬、眼神深邃、瞳孔骤缩、心中一凛、
五味杂陈、百感交集、不禁、不由自主、下意识、轻轻地、缓缓地、悠悠地、
空气仿佛凝固、沉默了片刻、陷入沉思、微微一愣、挑了挑眉、叹了口气、
呢喃、喃喃、缱绻、氤氲、涟漪、静谧、这一刻他明白了、整个世界都安静了
```
配套规则：`「——」「……」` 每 3 句 ≤1 次；禁止"不仅…而且…"式对偶；禁止首句复述对方。

### 4.6 采样参数（解决 P5）

`llm_client.chat` 增加可选参数，配置面板暴露（DeepSeek 为 OpenAI 兼容，均支持）：

| 参数 | 建议 | 说明 |
|---|---|---|
| `temperature` | 0.9~1.2（默认由 0.7 上调） | 提高多样性，降低模板腔 |
| `top_p` | 0.95 | 与温度配合 |
| `frequency_penalty` | 0.3~0.6 | 惩罚重复词，抑制"仿佛/一丝"复读 |
| `presence_penalty` | 0.2~0.4 | 鼓励新话题，减少复述 |
| `max_tokens` | 角色 400~600 | 防止长篇大论式"AI 作文" |

### 4.7 其余 Agent 提示词调整

| Agent | 调整 |
|---|---|
| **Director** | 旁白加「文风规范」：白描、客观、不抒情、不写角色心理、≤120 字；世界观改注入 `背景/规则`；禁止把 `排除/` 与评判标准带入 |
| **World Agent** | 增加检查项：视角越界（是否替他人心理）、是否出现反 AI 词表高频词、是否与角色卡「语言风格」冲突 |
| **Memory Manager** | 不变（只从角色本人发言抽取） |
| **Synopsis** | 沿用 |
| **Judge** | 新增 `ai_flavor`（AI 腔程度）评分，与 `persona_consistency` 并列，**均为观察项（in_gates=false）** |
| **Character Selector** | 不变 |

## 五、V4-3 去 AI 腔质量闭环（解决 P6）

- **双通道检测**：
  - 规则通道：反 AI 词表命中数 / 千字 → `ai_flavor_hit_rate`（可硬断言上限）。
  - LLM 通道：Judge 增加 `ai_flavor_score`（0~1）。
- **新增指标**（`backend/metrics.py`）：

| 指标 | 口径 | 类型 |
|---|---|---|
| `ai_flavor_hit_rate` | 反 AI 词命中数 / 角色发言千字 | 观察（设上限告警） |
| `example_injected` | 角色 prompt 是否含对话示例 | 门禁（=true） |
| `style_field_coverage` | 角色卡结构化字段（性格/语感/示例）覆盖率 | 观察 |
| `world_leak_from_excluded` | 排除目录内容是否漏进 prompt | 门禁（=0） |
| `third_person_leak` | 角色发言中替他人写心理/动作的命中数 | 门禁（=0） |

- **回归剧本扩充**：`backend/eval/fake_llm.py` 增加"AI 腔正例/反例"脚本，离线回放断言 `ai_flavor_hit_rate` 下降、`example_injected=true`。

## 六、V4-4 界面重构

### 6.1 凌乱文本串清单（截图逐条 + 根因 + 修复）

| # | 位置 | 现象（截图） | 根因 | 修复 |
|---|---|---|---|---|
| U1 | 观测面板指标卡 | `编排成功率 <span class="obs-badge pass">PASS</span>` 当文本显示 | `renderObservability()` 把含 HTML 的 label 又 `escapeHtml()`；`k.replace(/\s*<[^>]*>\s*$/,"")` 只删了结尾标签 | **badge 与文本分离渲染**（见 6.4 代码）；label 文本单独转义 |
| U2 | 观测面板卡片标签 | `轮次 完成/总`、`单轮 token 均值 24847` | 标签/数值表达别扭、未格式化 | 标签规范为「完成轮次」「单轮平均 Token」；数值 `24.8K`、`7.9s` |
| U3 | 观测·最近轮次 | `导演·director_plan 1826ms ｜ 世界·world_check 479ms ｜ …` 一行长串 | 调用图用 `｜` 平铺 | 改为**逐条步骤行 / 迷你条形图**（见 6.5） |
| U4 | 聊天区顶栏 | `世界：… · 知识库：C:\… · 时间：… · 地点：城郊废弃小花园（倒塌半边的石亭前）` 单行超长 | 单行拼接 | 改**两行 + chips**，路径中段省略加 `title` |
| U5 | 聊天区顶部第一条消息 | 文字重叠/凌乱 | 疑似被顶栏裁切 + 内容未规范化（`\r`、连续空行） | 顶栏 `position:sticky` 不透明 + `.messages{padding-top}`；渲染前规范化 `\r\n→\n`、折叠 3+ 空行（见 6.3） |

### 6.3 消息区改造清单

1. 顶栏：`.chat header { position: sticky; top: 0; z-index: 5; background: var(--bg2); }`；`.messages { padding-top: 16px; }`。
2. 内容规范化（渲染前）：`content.replace(/\r\n?/g,"\n").replace(/\n{3,}/g,"\n\n").trim()`。
3. **动作/对白分层**：把 `（…）`（含 `(...)`）切分为 `<span class="act">…</span>`，动作段用 `--text-dim` + 轻微斜体；对白正常色。
4. **时间分组**：同一分钟内的连续消息只显示一次时间戳。
5. 角色徽标：`导演` 用紫色徽标「场景描述」，角色用 `🧠 +N 条记忆` 徽标（已有）。
6. 空消息 / 纯动作消息（只回一个动作）也要能撑起气泡高度。

### 6.4 观测面板：badge 元素化（修复 U1）

```js
// 关键：label 文本单独转义，badge 作为独立元素拼接
function obsCard(label, value, gate) {
  const badge = gate ? `<span class="obs-badge ${gateClass(gate)}">${gate}</span>` : "";
  return `<div class="obs-card">
            <div class="k">${escapeHtml(label)}${badge}</div>
            <div class="v">${escapeHtml(String(value))}</div>
          </div>`;
}
function gateClass(s){ return s === "PASS" ? "pass" : s === "FAIL" ? "fail" : "base"; }

// 调用：obsCard("编排成功率", fmtPct(m.agent_orchestration_success_rate), m.gates?.agent_orchestration_success_rate)
```
> 删除原 `k.replace(/\s*<[^>]*>\s*$/,"")` 的补丁式写法。

### 6.5 观测面板：轮次调用图重构（修复 U3）

每条轮次改为**卡片 + 步骤行**：

```

  ⚠ 日期回退被拒
  ├─ 导演·规划    ▉▉▉▉▉▉▉▉▉▉ 1826ms
```
