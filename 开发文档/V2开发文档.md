# AI Drama 群聊剧情模拟系统 — V2 开发文档

> 版本：V2（正式产品化迭代）
> 本文档记录 V2 版本的全部改动。V1 及之前内容见《初版实现方案.md》《V1功能迭代.md》。

## V2 概览

V2 以"正式产品"标准对项目进行打磨，包含 7 部分改动：

1. **正式产品化清理**：移除前端 logo 上的 "V1-V4" 展示框；
2. **人物长期记忆编辑**：新增记忆管理 UI（查看 + 增删改 + 持久化），使记忆可由人工修正；
3. **角色命名通用化**：根治"角色名含 `/` 导致资料卡 404"问题——文档名优先 + 标题别名 + query 参数传名；
4. **GitHub 发布**：上传到 GitHub（公开仓库 `AI-Drama-Public`），配置代理与凭据缓存；
5. **导演 Agent 化 + 长期记忆**：导演升级为有长期记忆的正式 Agent，调度需求沉淀复用；
6. **角色 / Agent 分离 + 单Agent对话（场外）**：区分知识库"角色"与群聊"Agent"，去掉导演沟通/单角色对话，改为场外单Agent对话。
7. **Agent 面板透明化 + 功能 Agent 详情/记忆**：面板展示全部真实 Agent（角色 + 导演）并带角色徽标；功能 Agent（导演）同样可查看详情与读写长期记忆。

# 迭代3：角色命名通用化（文档名优先 + 标题别名 + query 参数）

## 背景与根因
角色「兰 / 代号B」「C / 代号C」资料卡加载失败，报 404 "Not Found"。

排查结论：
- 角色名此前取自**文档 `# 标题`**（`B（代号B）.md` 内标题为 `# 兰 / 代号B`），名字含 ASCII 斜杠；
- 前端 `encodeURIComponent` 把 `/` 编码为 `%2F`，但 **uvicorn 路由匹配前会把 `%2F` 解码回 `/`**，
  路径被拆成多余一段；路由 `{name}` 只匹配非斜杠字符 → 匹配不到 → 404；
- 这不是脚本写死名字，而是"名字来源（标题）不可控"导致的架构问题。

## 方案（通用化，非逐案修补）
1. **角色名以文档文件名为准**：`_extract_name` 改为返回 `(规范名, 标题别名)`，
   规范名 = 清理后的文件名（`B（代号B）.md` → `B（代号B）`），不再被标题覆盖；
2. **文档标题降级为别名**：`character_aliases` 记录"标题 → 规范名"，
   `resolve_character` 匹配顺序改为：规范名精确 → 标题别名 → 子串 → 去括号核心名，
   因此"代号B""C""兰 / 代号B（旧名）"都能解析到规范名；
3. **接口通用化**：角色名一律走 **query 参数**（`?name=...`），不再放 URL 路径：
   - `GET /api/sessions/{sid}/character?name=`
   - `PUT /api/sessions/{sid}/character/memory?name=`
   任何字符（`/`、空格、全角符号）都由 query 标准解析，彻底杜绝同类问题；
4. **存量会话迁移**：`runtime.restore_agents` 对旧名 Agent 用 `resolve_character`
   解析到新规范名后注册，**记忆与资料完整保留**（记忆文件因 sanitize 规则恰好同名，无需搬文件）。

## 涉及文件
`backend/knowledge_base.py`、`backend/main.py`、`backend/runtime.py`、
`frontend/app.js`（3 处调用改 `?name=`）、`开发文档/API接口参考.md`

## 验证
| 项 | 结果 |
|---|---|
| 规范名 | `B（代号B）`、`C（代号C）`、`D`（均为文档名） |
| 别名解析 | "代号B"→`B（代号B）`；"C"→`C（代号C）`；旧名"兰 / 代号B"→`B（代号B）` |
| 详情接口 | `?name=` 方式：A 5692 字 / B（代号B）457 字 / C（代号C）1784 字，全部 200 |
| 记忆接口 | `?name=` 方式 PUT 记忆 200 成功 |
| 存量会话 | 「示例世界」Agent 已自动迁移为新规范名 |

# 迭代5：导演 Agent 化 + 导演长期记忆（调度备忘）

## 背景
把导演从"每轮临时构建的无状态调度器"升级为**有长期记忆的正式 Agent**，
让调度需求/偏好沉淀下来，避免用户每次提供需求都要重新附带最近对话。

## 后端
1. `Agent` 增加 `role` 字段：`character`（默认）/ `director`；
2. `runtime.create_director_agent()`：会话创建时实例化「导演」Agent（role=director），
   注册到 Registry，持久化到 `data/sessions/<sid>/characters/导演.json`；
3. 导演长期记忆：与角色同机制（long_memory，去重、上限 80 条）；
4. 记忆抽取：从"调度沟通/群聊调度"中提炼用户的长期偏好、已确认的选角/方向等，存入导演长期记忆；
5. 群聊调度时，向导演规划消息注入【导演长期记忆·调度备忘】（场外参考，不写入群聊转录）。

## 前端
- 导演作为 Agent 出现在 Agent 面板（含状态/记忆条数/记忆编辑入口）。

## 说明（演进记录）
此迭代同时引入了"导演沟通模式"（导演 1v1 与用户讨论调度）。该模式在后一迭代（迭代6）
被"单Agent对话（场外）"取代，最终未保留独立模式。

## 涉及文件
`backend/agents.py`、`backend/runtime.py`、`backend/session.py`、`backend/director.py`、
`backend/prompts.py`、`backend/main.py`、`frontend/`

## 验证
- 会话中新增导演 Agent（role=director、active）；
- 导演沟通/调度后，导演长期记忆自动抽取并落盘；
- 群聊规划中注入导演调度备忘，需求跨轮次生效。

# 迭代6：角色 / Agent 分离 + 单Agent对话（场外）

## 背景
明确区分两个概念：
- **角色** = 知识库维护的角色档案 + 长期记忆（资料源，可人工编辑记忆）；
- **Agent** = 群聊中**实际运行**的实例（角色实例 + 导演等功能性 Agent）。

并**去掉"导演沟通"与"单角色对话"**，改为**单Agent对话（场外）**——可与任意 Agent 1v1 沟通，
用于场外调整，**不进入群聊情节记忆**。

## 后端
1. `session.py`：`side_chats`（按 Agent 名 → 消息列表，持久化）替代 `director_chat`；
2. `director.py`：新增 `run_agent_turn(agent_name, user_input)` —— 目标 Agent 用
   自己的 system_prompt + 自己的场外记录 1v1 回复，**不写入群聊转录、不抽取记忆、不更新梗概**；
3. `main.py`：
   - 新增 `POST /api/sessions/{sid}/chat/agent`（请求体含 `agent_name`）；
   - 新增 `GET /api/sessions/{sid}/side_chat/{agent}`；
   - 移除 `POST /chat/single`、`POST /chat/director`、`GET /director_chat`。

## 前端
1. 右侧页签改为 **「角色 / Agent / 世界」**：
   - 角色页签 = 知识库角色档案 + 记忆编辑（`#char-list`）；
   - Agent 页签 = 群聊运行实例（`#agent-list`，含导演，生命周期 + 记忆编辑）；
   - 世界页签不变。
2. 模式下拉改为 **「群聊模式 / 单Agent对话」**（删除 单角色对话、导演沟通）；
3. 选中「单Agent对话」时，模式框左侧出现 **Agent 选择框**（直读 Agent 页签实例列表）；
4. 聊天区按模式显示：群聊 → 群聊转录；单Agent → 该 Agent 的场外对话记录（`/side_chat`）。

## 涉及文件
`backend/session.py`、`backend/director.py`、`backend/main.py`（移除 `/chat/single`、
`/chat/director`、`/director_chat`；新增 `/chat/agent`、`/side_chat/{agent}`）、
`frontend/index.html`（三页签、单Agent模式、Agent选择框）、`frontend/app.js`、

# 迭代7：Agent 面板透明化 + 功能 Agent 详情/记忆

## 背景
Agent 面板应完整展示**真实存在的群聊 Agent 构成**（角色 Agent + 功能 Agent，如导演），
同时每个 Agent（功能 Agent 也不例外）都应能**查看详情与读写其长期记忆**，让群聊对用户透明。

## 说明：旁白不是独立 Agent
群聊中的“旁白”由**导演生成**、归属导演写入转录，**并非独立运行的 Agent**。
因此本迭代**不虚构旁白 Agent**，只展示真实存在的 Agent（角色 + 导演）。

## 后端
1. `runtime.get_or_create_agent(name)`：已有则返回；`导演` → `create_director_agent()`；
   否则按知识库角色 `create_agent()`；功能 Agent（导演）不因“非知识库角色”而落空。
2. `runtime.refresh_prompt(agent)`：按 `agent.role` 重建对应 System Prompt
   （director → 导演 Prompt，其余 → 角色 Prompt），取代原来的按角色硬编码刷新。
3. `GET /character?name=`（详情）：Agent 改为从 **Registry** 取（不要求是知识库角色），
   返回新增 `role` 字段；`profile` 对功能 Agent 回退到 `agent.profile`。
   → 导演可读其详情（状态/资料/情感/关系/长期记忆/技能）。
4. `PUT /character/memory?name=`（写记忆）：改用 `get_or_create_agent` + `refresh_prompt`，
   功能 Agent（导演）也能整表替换长期记忆并落盘、按导演 Prompt 重建。

## 前端
1. Agent 卡片统一角色徽标：`· 角色` / `· 导演`（一目了然群聊构成）。
2. Agent 卡片新增「📄 详情」按钮（复用详情弹窗），任意 Agent（含导演）可查看详情记忆。
3. 「🧠 记忆」编辑器对功能 Agent（导演）同样可用。
4. **不虚构旁白**：列表只展示真实 Agent（角色 + 导演）。

## 涉及文件
`backend/runtime.py`、`backend/main.py`、`frontend/app.js`；文档 `开发文档/API接口参考.md`。

| 项 | 结果 |

| 导演详情 | `GET /character?name=导演` 返回 role=director、status、profile、记忆 |

# 迭代8：Agent 面板分组 + 角色 Agent 懒创建

## 背景
- 让 Agent 面板**功能 Agent 置顶、与角色 Agent 分开**，群聊构成更清晰。
- 对齐《群聊剧情模拟说明文档》的“**角色 Agent 动态创建**”：不再在会话启动时预实例化全部角色，
  改为**首次参与群聊时才懒创建**，避免为从不参与的角色白建实例。

## 关于 Token 的澄清
预创建角色**不直接消耗 LLM token**（`build_character_system_prompt` 仅本地拼字符串，非 API 调用；
token 只在角色实际发言时的 `chat` 请求中消耗）。因此“全部预创建”的真实代价是**冗余的记忆文件 /
Registry 内存 / 面板很长**，而非 token；懒创建的收益主要是整洁与对齐文档。

## 前端
- `renderAgentPanel` 按 `role` 分两区：**功能 Agent（role≠character）置顶**，**角色 Agent（role=character）在下**，
  各带小标题；`agentSectionTitle` 生成分区标题。
- Agent 面板**角色区只显示“已创建”的角色**；未创建的角色在“角色(知识库)”页签仍可见（状态“未实例化”）。

## 后端
- `session._restore`：**不再** `for name in kb.character_names(): create_agent(name)`；
  改为只 `create_director_agent()`，角色在首次参与群聊 / 显式 `POST /agents/create` / 详情·记忆编辑时按需创建
  （`director.ensure` 与 `runtime.get_or_create_agent` 已支持懒创建）。

## 涉及文件
`backend/session.py`、`frontend/app.js`、`frontend/style.css`；文档 `开发文档/API接口参考.md`（如需）。

## 验证
| 项 | 结果 |
|---|---|
| 新建会话 `/agents` | 仅 `[导演(director)]`，不再预建全部角色 |
| `/characters` | 仍列出全部知识库角色，未创建者状态“未实例化” |
| 懒创建 | `POST /agents/create A` 后 `/agents` 出现 `[导演, A]` |
| 前端 | 功能 Agent 在上、角色 Agent 在下，分区展示 |

# 迭代9：群聊多 Agent 协同（推荐方案落地）

## 背景
对齐《群聊剧情模拟说明文档》的“多个 Agent 共同维护群聊，剧情受世界观与人设约束”，
按“推荐最佳方案”落地：**导演编排 + 关键功能 Agent 独立 + 数据组件轻量化**。

## 组成
| Agent | role | 是否 LLM | 触发 | 记忆 |
|---|---|---|---|---|
| 导演 Director | director | ✅ | 每轮（编排核心） | 调度备忘 |
| 世界 World Agent | world | ✅ | **世界状态变化时**（增量触发） | 可编辑 |
| 记忆管理 Memory Manager | memory | ✅ | 每轮发言后 | 各角色长记忆 |
| 梗概 Synopsis Agent | synopsis | ✅ | 节流（每 N 条） | 梗概 |
| 时间线 Timeline/Event | timeline | ❌ 纯数据组件 | 每次事件 | 无（WorldState） |
| 角色 Character Agents | character | ✅ | 被调度发言时 | 长记忆/情感/关系 |

## 实现
- `runtime.py`：新增功能性 Agent 创建 `create_functional_agents()` / `create_functional_agent(name)` /
  `_functional_prompt(role)`；`refresh_prompt` 与 `get_or_create_agent` 支持 `world/memory/synopsis`。
- `session.py`：`_restore` 创建 导演 + 世界 + 记忆管理 + 梗概。
- `director.py`：
  - **世界校验默认开启、增量触发**（仅当 时间/地点/时段 变化时才调用，省 token；结果场外隔离，不写转录/记忆）；
  - world_check / extract_memories / update_synopsis 分别用对应功能 Agent 的 system_prompt（可在详情/记忆界面编辑）；
  - **参与者过滤**：群聊只允许 `role=="character"` 参与；`_fallback_participants` 也只选角色（功能 Agent 不参与发言）。

## 涉及文件
`backend/runtime.py`、`backend/session.py`、`backend/director.py`；文档 `开发文档/群聊多Agent化方案.md`。

## 验证
| 项 | 结果 |
|---|---|
| 新建会话 `/agents` | 导演 / 世界 / 记忆管理 / 梗概（功能 Agent）均在；角色仍懒创建 |
| 功能 Agent 提示词 | 详情返回非空 system_prompt（世界/记忆/梗概） |
| 群聊参与者 | 只含角色 Agent；功能 Agent 不发言 |
| 世界校验 | 世界状态变化时执行、结果不污染转录/记忆 |
| 前端 | 功能 Agent 置顶分组（世界/记忆/梗概/导演） |
