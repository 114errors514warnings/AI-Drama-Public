## 三、改造方案（分批）

### 阶段 0：安全与便携（P0，必须先做）

| 任务 | 具体改动 |
|---|---|
| 0.1 配置**环境变量化** | `AIDRAMA_API_KEY / BASE_URL / MODEL / DATA_DIR / HOST / PORT / KB_ROOT / PROVIDER`；优先级：env > `data/config.json` > 内置默认；删除硬编码 `<本机路径>`（保留为"可选兜底 + 文档说明关闭方法"或直接删除） |
| 0.2 密钥不再明文落盘 | 默认只从 env 读；UI 写入改为可选（并明确告警）；可选 `keyring` |
| 0.3 **知识库根沙箱** | 新增 `AIDRAMA_KB_ROOT`；设置后 `/api/kb/browse` 与 `validate` 只允许该根目录内路径，越界返回 403 |
| 0.4 **native-pick 降级** | 非 Windows / 无桌面 / `AIDRAMA_KB_ROOT` 已设时，接口返回 501 并提示"手填路径"；前端按钮在该情况隐藏 |
| 0.5 可选**鉴权开关** | `AIDRAMA_AUTH_TOKEN` 设置后，除 `/api/health` 与静态资源外全部要求 `Authorization: Bearer` |
| 0.6 容器加固 | `Dockerfile` 改非 root 用户、`HEALTHCHECK`、`.dockerignore` 补 `.github/` `examples/` 等 |
| 0.7 `GET /api/health` | 返回 `{status, version, llm_provider, demo_mode, data_dir_writable}` |

**验收**：在无 `<本机路径>` 的干净机器/容器上，仅用环境变量即可启动并完成一次对话；`browse` 越界被拒；非 Windows 下前端不再出现"浏览"按钮。

## 九、双仓库开发与发布流程

**约定：日常开发仍在开发仓库进行；公开仓库只在明确确认时才更新。**

| 角色 | 位置 | 说明 |
|---|---|---|
| 开发仓库（私用，唯一开发场所） | 本机项目目录 | 保留全部历史与过程文档；可自由引用个人素材（但**不要**提交到会被导出的文件里） |
| 公开仓库（对外发布） | `114errors514warnings/AI-Drama-Public` | 由开发仓库**单向同步**；单一初始提交起步，历史干净 |
| 同步脚本（本机、不入库） | `scripts/publish-public.ps1` | 已加入 `.gitignore`，不会发布 |

### 流程

```powershell
# 1) 预览（安全扫描 + 差异预览；不提交、不推送）
.\scripts\publish-public.ps1

# 2) 确认无误后，才执行同步（提交 + 推送到公开仓库）
.\scripts\publish-public.ps1 -Push
```

### 脚本做了什么（安全兜底）

1. `git archive HEAD` **只导出已跟踪文件** → `data/`、`*.log`、`.env` 等天然不会被带走。
2. **强制安全扫描**：命中 `人名/地名/世界观`、`本机盘符路径`、`Key 文件名`、`示例密钥前缀` 等任一模式即**中止**，不复制、不提交。
3. 镜像到公开仓库工作区，但**保留**公开仓库自有的 `.gitattributes`、`.env.example`，且不动 `data/`。
4. 打印差异；**默认不提交**。加 `-Push` 才 `commit` + `push`。
5. 公开仓库 `origin` = SSH（本机已配好 key，`ssh -T git@github.com` 通过）；脚本默认推 `origin`，如需走 HTTPS 可加 `-Remote https`。

### 注意

- 预览会更新公开仓库的**工作区**但不提交；想放弃：`git -C "<公开仓库目录>" reset --hard; git -C "<公开仓库目录>" clean -fd`
- 公开仓库与开发仓库的 `.gitattributes` / `.env.example` 是**公开仓库独有**的，同步时不会被覆盖。
- 若日后开发仓库又引入真实作品设定，脚本会在第 2 步拦下——这是最后一道闸门。
